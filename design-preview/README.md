# Дизайн-превью

Изолированный React/Vite-инструмент для просмотра будущих визуальных решений. Это не стек продукта хакатона. Реестр `src/catalog/entries.ts` намеренно пуст: сначала разбирается ТЗ и согласовывается направление дизайна. Категории и нейтральные структурные стили можно заменить под проект; они не задают палитру, шрифт или тему продукта.

## Запуск

Требуются Node.js 24.13+ (ветка 24) и pnpm 10.29.3.

```bash
cd design-preview
pnpm install --frozen-lockfile
pnpm dev
```

Откройте адрес, который напечатает Vite (обычно http://127.0.0.1:5173). Сервер слушает только loopback. Для проверки production-сборки: `pnpm build`, затем `pnpm preview`. `pnpm typecheck` запускает только TypeScript. Сборка находится в `dist/`; hash-маршрутизация и относительная база позволяют размещать её в подкаталоге статического хостинга без серверных rewrite-правил. Локальный запуск не является публичным развёртыванием.

## Что есть в оболочке

Обзор, верхняя навигация, боковой список категорий, страницы категорий, поиск по названиям и описаниям, маршрут деталей `/entries/:id` и область будущего превью. Адреса находятся после `#`, например `#/categories/input`. Неизвестные адреса и отсутствующие примеры имеют понятные состояния. Поиск хранит запрос в URL и показывает пустой результат; он начнёт находить примеры только после заполнения реестра.

Навигация использует обычные ссылки, поиск — подписанное поле и кнопку. Есть переход к содержимому, перевод фокуса в основной регион после навигации, заметный фокус, адаптивная раскладка и обработка `prefers-reduced-motion`. Это свойства реализации, а не утверждение о выполненной браузерной проверке.

## Контракт будущего наполнения

Типы экспортируются из `src/catalog/types.ts`, массивы — из `categories.ts` и `entries.ts`.

- `DesignCategory`: стабильный уникальный `slug`, `title`, краткое `description`.
- `DesignSource`: `kind` (`original` или `adapted`), `name`, `url`, `license`, необязательный `revision`, короткий `adaptationNote`.
- `DesignEntry`: стабильный уникальный `id`, `title`, `categorySlug` существующей категории, `summary`, список названий `states`, React-компонент `Preview` без обязательных props и метаданные `source`.

Используйте URL-безопасные стабильные slug/id. Имена состояний внутри записи должны быть уникальными. Для оригинальной работы укажите автора/проект, ссылку на исходник в репозитории, его лицензию и короткую заметку об оригинальной реализации. Для адаптации укажите исходный источник, лицензию, проверенную ревизию при наличии и сделанные изменения. Лицензию и доступность источника проверяют перед переносом.

После согласования направления создайте нужный компонент внутри `src/`, реализуйте заявленные состояния в его превью и зарегистрируйте запись в `entries`. Страница детали отобразит компонент, названия состояний и источник. Не подключайте локальные каталоги через относительные пути, алиасы, symlink или файловый импорт. Добавляйте зависимости только для конкретной согласованной возможности после проверки совместимости, лицензии, адаптивности и доступности.

В стартере нет дизайн-примеров, сторонних компонентов, медиа, шрифтов, тем или библиотек иконок. Входной ТЗ, секреты и данные пользователей этому инструменту не требуются. Тестовый набор намеренно не добавлен.
