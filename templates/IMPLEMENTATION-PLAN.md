## Текущее состояние

- P0 реализован в статическом фронтенде: каталог, рулетка, инвентарь, апгрейд, батлы и демо-пополнение.
- Навигация не зависит от глобального `event`; апгрейд фиксирует цель и шанс; предпросмотр инвентаря read-only.
- Баланс и инвентарь сохраняются в `localStorage` (`so2cases.demo.v1`), есть подтверждаемый сброс.
- Выбрано и реализовано направление C «Честная витрина»; `design-preview/` остаётся пустым.
- Бэкенд Express/Mongoose существует, но не связан с UI.
- Проверки P0 выполнены в Chromium и на 375 px; Safari и интерактивный Firefox не проверены, автоматических тестов нет.

### Статус P0 на 2026-11-19

- P0-1…P0-8 реализованы в коде и описаны в README.
- Полный пользовательский сценарий пройден в Chromium: кейс → выигрыш → продажа/инвентарь → предпросмотр → апгрейд → пополнение → батл → перезагрузка → сброс.
- Проверены `Escape`, удержание и возврат фокуса, фоновая блокировка, `aria-live`-уведомления.
- Lighthouse: Accessibility 100, Best Practices 100, SEO 100, без проваленных аудитов.
- 375 × 812: все разделы без горизонтального скролла, цели не меньше 44 px, нижняя навигация не перекрывает футер.
- Проверены сохранение после перезагрузки, повреждённый `localStorage`, санитизация данных и fallback изображений.
- Firefox проверен только рендер-скриншотами (375 и 1440 px); Safari не проверен, remote automation выключена.
- `prefers-reduced-motion` проверен подменой `matchMedia`; системная настройка ОС не использовалась.
- Автоматических тестов нет (P1-7); публичного развёртывания нет.

## Стек и архитектура

- **P0:** сохранить статический фронтенд без сборки. Это снижает риск демо и сохраняет возможность открыть `index.html` напрямую.
- **Состояние:** единый объект `{ version, balance, inventory }` в `localStorage`; функции чтения/записи с обработкой ошибок; сброс.
- **Логика:** вынести чистые функции выбора предмета, расчёта шанса и применения результата в отдельные функции внутри `js/main.js` (без сборки). При росте сложности — P1-рефакторинг на модули и обязательный локальный сервер.
- **Бэкенд:** не входит в P0. Для P1 — API состояния демо-пользователя, а не публичный CRUD. Не выставлять `/api/users` в интернет без аутентификации и валидации.
- **Дизайн:** не менять визуальный язык до выбора направления; P0-правки не должны требовать редизайна.
- **Запасной вариант:** только статический фронтенд, без MongoDB и внешней сети; изображения с fallback.

## Риски и запасные варианты

| Риск | Влияние | Смягчение |
|---|---|---|
| Оригинальное ТЗ не найдено | Можно полировать не то, что оценивают | P0 ограничен текущими функциями; вопросы в `brief.md`; не добавлять крупные функции |
| Внешний CDN изображений недоступен | Демо выглядит пустым | `onerror`-заглушки; P1-5 локальные ассеты после проверки прав |
| MongoDB или API недоступны | Показ останавливается | Бэкенд вне P0; фронтенд работает автономно |
| Апгрейд меняет поведение и ломает демо | Потеря ключевой механики | Сначала тест-сценарий, затем правка; проверка на пустом инвентаре и при перезагрузке |
| Мобильная вёрстка требует редизайна | Выход за P0 | Сначала исправить навигацию и переполнение; глубокий редизайн — после выбора направления |
| Смешение демо и реальных обещаний | Репутационный риск | P0-1: явные подписи и честный README |
| Нет тестов | Регрессии | P1-7; ручной чек-лист в P0-8 |

## План демо

1. Открыть главную, показать баннер демо-режима.
2. Показать каталог и фильтр.
3. Открыть «Стартовый кейс» за 25 ₽, прокрутить, получить скин.
4. Продать скин; показать обновление баланса.
5. Открыть ещё один кейс, оставить предмет в инвентаре.
6. Перейти в инвентарь: предпросмотр (read-only), затем продажа.
7. Открыть апгрейд: выбрать предмет, увидеть цель и шанс, выполнить попытку.
8. Перезагрузить страницу и показать сохранённое состояние.
9. Нажать «Сбросить демо» и вернуть исходное состояние.
10. Назвать ограничения: имитации, отсутствие реальных платежей, внешние изображения.
