# Foksik Case (SO2 CASES)

Демо-сервис открытия кейсов Standoff 2: каталог кейсов, рулетка, выигрыш, инвентарь, продажа скинов, апгрейд и демо-батлы. Репозиторий также является площадкой для методологии [Hackathon OS](https://github.com/SamuraiSBS/hackathon-os): продуктовая логика, план, решения, исследование и демо ведутся в `templates/` и `docs/`.

> **Демо.** Реальных платежей, авторизации, вывода средств и многопользовательской игры нет. Пополнение баланса, лайв-фид, «онлайн» и батлы имитируются. Это явно показано в интерфейсе и должно проговариваться на защите.

## Что уже работает (P0)

- каталог из 12 кейсов с фильтрами по категориям;
- рулетка открытия кейса с весами предметов;
- выигрыш с действиями «продать», «в инвентарь», «оставить и ещё раз»;
- инвентарь, read-only предпросмотр, продажа одного предмета и продажа всего;
- апгрейд: пользователь выбирает свой предмет, цель и шанс фиксируются при выборе, успех выдаёт именно показанную цель;
- демо-пополнение баланса с лимитом на операцию;
- демо-батлы с явной пометкой «синтетический»;
- сохранение баланса и инвентаря в `localStorage` (ключ `so2cases.demo.v1`);
- кнопка «Сбросить демо» с подтверждением: возвращает 1 250 ₽ и пустой инвентарь;
- доступные модальные окна: `role="dialog"`, `aria-modal`, удержание фокуса, `Escape`, возврат фокуса, блокировка фоновой прокрутки;
- `prefers-reduced-motion`: рулетка укорачивается, конфетти и плавный скролл отключаются;
- локальная SVG-заглушка для недоступных изображений;
- Express API с CRUD пользователей (не подключён к фронтенду).

## Быстрый старт: фронтенд

Сборка не нужна. Рекомендуется локальный сервер, чтобы `localStorage` и внешние изображения работали одинаково в разных браузерах:

```bash
# из корня проекта
python3 -m http.server 8000
# или
npx serve .
```

Откройте `http://localhost:8000`.

Можно открыть и `index.html` напрямую, но локальный сервер надёжнее для демонстрации.

## Быстрый старт: бэкенд

```bash
cd foksik_case_backend
npm install
```

Создайте `foksik_case_backend/.env`:

```env
PORT=3000
NODE_ENV=development
MONGODB_URI=mongodb://127.0.0.1:27017/foksik_case
```

Убедитесь, что MongoDB запущена, затем:

```bash
npm run dev    # с автоперезагрузкой
npm start      # обычный запуск
```

Проверка: `curl http://localhost:3000` → `{"message":"Welcome to Foksik Case Backend API"}`.

API: `GET /`, `/api/users` (CRUD, демонстрационный, без авторизации — не выставлять в интернет).

## Демо-сценарий (2–3 минуты)

1. Открыть главную: показать баннер демо-режима, метки «синтетические данные» и отсутствие реальных платежей.
2. Выбрать категорию кейсов и открыть «Стартовый кейс» за 25 ₽.
3. Прокрутить рулетку, получить скин. Показать, что предмет уже лежит в инвентаре, и выбрать «Продать» или «В инвентарь».
4. Перейти в инвентарь: открыть предпросмотр (только просмотр, без изменения баланса), затем продать предмет.
5. Открыть ещё один кейс и оставить предмет в инвентаре.
6. Перейти в апгрейд: выбрать предмет, показать зафиксированные цель и шанс, выполнить попытку. При успехе выдаётся показанная цель, при неудаче предмет теряется.
7. Открыть демо-пополнение, выбрать сумму и показать обновление баланса.
8. Открыть батл, подчеркнуть, что соперники и результат синтетические; дождаться демо-результата.
9. Перезагрузить страницу и показать, что баланс и инвентарь сохранились.
10. Нажать «Сбросить демо», подтвердить и вернуть исходные 1 250 ₽ с пустым инвентарём.
11. Назвать ограничения: нет реальных платежей, авторизации, вывода и мультиплеера; данные хранятся только в этом браузере; изображения и шрифт загружаются с внешнего CDN.

Выполнено:

- сохранение состояния после перезагрузки, восстановление после повреждённого `localStorage`, санитизация подменённых данных инвентаря;
- клавиатура и фокус: Tab внутри модалок, `Escape`, возврат фокуса, блокировка фона;
- fallback изображения при ошибке загрузки;
- Lighthouse: Accessibility 100, Best Practices 100, SEO 100, без проваленных аудитов;
- 375 × 812: все четыре раздела без горизонтального скролла, интерактивные цели не меньше 44 px, нижняя навигация не перекрывает футер;
- Firefox: headless-рендер на 375 × 812 и 1440 × 1000 для проверки раскладки;

Не проверено или проверено частично:

- Safari: remote automation выключена, интерактивный прогон не выполнялся;
- Firefox: только рендер-скриншоты, без интерактивного сценария;
- `prefers-reduced-motion` проверен подменой `matchMedia`, а не системной настройкой ОС;
- автоматических тестов нет — это P1-7;
- публичного развёртывания нет, все проверки локальные.

## Известные ограничения

- баланс и инвентарь хранятся только в `localStorage` текущего браузера, не синхронизируются между устройствами;
- пополнение виртуальное: до 100 000 ₽ за операцию, верхний предел баланса — 10 000 000 ₽;
- лайв-фид и «онлайн» синтетические;
- батлы имитируются и всегда завершаются демо-предметом; это не соревнование с реальными игроками;
- цель апгрейда подбирается автоматически по цене источника; выбор цели пользователем — P1;
- изображения предметов и шрифт Inter загружаются с внешнего CDN; при ошибке изображения показывается локальная заглушка, локальные лицензированные ассеты — P1;
- бэкенд не связан с фронтендом; публичный `/api/users` нельзя выставлять в интернет без аутентификации и ограничения прав;
- реальных платежей, авторизации, вывода средств и мультиплеера нет;
- автоматических тестов нет.

## Hackathon OS в проекте

Рабочий цикл:

1. `brief.md` — исходные вводные и открытые вопросы.
2. `templates/CHALLENGE-BRIEF.md` — структурированные требования и допущения.
3. `templates/PRODUCT-BRIEF.md` — пользователи, сценарий, правила, состояния.
4. `templates/RESEARCH-LOG.md` — источники, факты и гипотезы.
5. `templates/PRODUCT-DECISIONS.md` — журнал решений.
6. `templates/IMPLEMENTATION-PLAN.md` — P0 / P1 / P2 и критерии приёмки.
7. `templates/DESIGN-DIRECTION.md` — направления дизайна и статус выбора.
8. `templates/RETROSPECTIVE.md` — итоги после демо.

Правила работы агента — `AGENTS.md`, полный цикл — `docs/WORKFLOW.md`.

### Дизайн-превью

Выбрано направление **C. «Честная витрина»**: графитовая база, изумрудный акцент, плоские поверхности, сохранённые цвета редкостей. Оно реализовано напрямую в продукте.

`design-preview/` остаётся пустым: в окружении нет pnpm и требуемой ветки Node.js, поэтому React/Vite-превью не запускалось. Это осознанное отклонение, зафиксированное в `templates/DESIGN-DIRECTION.md`. React/Vite — стек инструмента превью, а не продукта.
