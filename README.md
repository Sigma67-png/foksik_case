# Foksik Case (CS2)

Веб-сервис открытия кейсов CS2: каталог кейсов, рулетка, выигрыш, инвентарь, продажа скинов, апгрейд и батлы. В каталоге — 208 реальных скинов CS2 с PNG и ценами Steam Community Market. Репозиторий также является площадкой для методологии [Hackathon OS](https://github.com/SamuraiSBS/hackathon-os): продуктовая логика, план, решения и исследование ведутся в `templates/` и `docs/`.

> Баланс, инвентарь и ставки хранятся только в этом браузере. Реальных платёжных интеграций, авторизации, вывода средств и мультиплеера нет.

## Что уже работает

- компактная закреплённая шапка с аватаром foksik_yt, меткой CS2 и навигацией;
- каталог из 13 кейсов с фильтрами по категориям;
- каталог 208 скинов: 10 популярных оружий по 10 скинов, 24 остальных по 3, все 20 ножей и 16 перчаток;
- PNG и цены взяты со Steam Community Market; снимок цен — 27.11.2026;
- рулетка открытия кейса с весами предметов;
- выигрыш с действиями «продать», «в инвентарь», «оставить и ещё раз»;
- инвентарь, предпросмотр, продажа одного предмета и продажа всего;
- апгрейд: пользователь выбирает свой предмет, цель из доступных и шанс 5–90%, успех выдаёт именно выбранную цель;
- пополнение баланса с лимитом на операцию;
- батлы;
- сохранение баланса и инвентаря в `localStorage` (ключ `foksik.case.v1`, старый ключ мигрируется);
- кнопка «Сбросить прогресс» с подтверждением: возвращает 1 250 ₽ и пустой инвентарь;
- доступные модальные окна: `role="dialog"`, `aria-modal`, удержание фокуса, `Escape`, возврат фокуса, блокировка фоновой прокрутки;
- `prefers-reduced-motion`: рулетка укорачивается, конфетти и плавный скролл отключаются;
- локальная SVG-заглушка для недоступных изображений;
- Express API с CRUD пользователей (не подключён к фронтенду).

## Быстрый старт: фронтенд

Сборка не нужна. Рекомендуется локальный сервер, чтобы `localStorage` и внешние изображения работали одинаково в разных браузерах:

```bash
# из корня проекта
python3 -m http.server 8000
# или
npx serve .
```

Откройте `http://localhost:8000`.

Можно открыть и `index.html` напрямую, но локальный сервер надёжнее для демонстрации.

## Быстрый старт: бэкенд

```bash
cd foksik_case_backend
npm install
```

Создайте `foksik_case_backend/.env`:

```env
PORT=3000
NODE_ENV=development
MONGODB_URI=mongodb://127.0.0.1:27017/foksik_case
```

Убедитесь, что MongoDB запущена, затем:

```bash
npm run dev    # с автоперезагрузкой
npm start      # обычный запуск
```

Проверка: `curl http://localhost:3000` → `{"message":"Welcome to Foksik Case Backend API"}`.

API: `GET /`, `/api/users` (CRUD, демонстрационный, без авторизации — не выставлять в интернет).

## Сценарий (2–3 минуты)

1. Открыть главную и посмотреть каталог кейсов.
2. Выбрать категорию и открыть «Стартовый кейс».
3. Прокрутить рулетку, получить скин и выбрать «Продать» или «В инвентарь».
4. Перейти в инвентарь: открыть предпросмотр, затем продать предмет.
5. Открыть ещё один кейс и оставить предмет в инвентаре.
6. Перейти в апгрейд: выбрать свой скин, затем цель и шанс 5–90%. При успехе выдаётся выбранная цель, при неудаче предмет теряется.
7. Открыть пополнение, выбрать сумму и показать обновление баланса.
8. Открыть батл и дождаться результата.
9. Перезагрузить страницу и показать, что баланс и инвентарь сохранились.
10. Нажать «Сбросить прогресс», подтвердить и вернуть 1 250 ₽ с пустым инвентарём.
11. Назвать ограничения: данные хранятся только в этом браузере, изображения и шрифт загружаются с внешнего CDN.

## Известные ограничения

- баланс и инвентарь хранятся только в `localStorage` текущего браузера и не синхронизируются между устройствами;
- пополнение локальное: до 100 000 ₽ за операцию, верхний предел баланса — 10 000 000 ₽;
- цены — снимок Steam Community Market, а не live-котировки;
- изображения предметов и шрифты загружаются с внешнего CDN; при ошибке изображения показывается локальная заглушка;
- бэкенд не связан с фронтендом; публичный `/api/users` нельзя выставлять в интернет без аутентификации и ограничения прав;
- автоматических тестов нет.

## Hackathon OS в проекте

Рабочий цикл:

1. `brief.md` — исходные вводные и открытые вопросы.
2. `templates/CHALLENGE-BRIEF.md` — структурированные требования и допущения.
3. `templates/PRODUCT-BRIEF.md` — пользователи, сценарий, правила, состояния.
4. `templates/RESEARCH-LOG.md` — источники, факты и гипотезы.
5. `templates/PRODUCT-DECISIONS.md` — журнал решений.
6. `templates/IMPLEMENTATION-PLAN.md` — P0 / P1 / P2 и критерии приёмки.
7. `templates/DESIGN-DIRECTION.md` — направления дизайна и статус выбора.
8. `templates/RETROSPECTIVE.md` — итоги после демо.

Правила работы агента — `AGENTS.md`, полный цикл — `docs/WORKFLOW.md`.
