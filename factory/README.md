# Фабрика агентов Foksik Case

Компактная кросс-функциональная команда для сайта открытия кейсов CS2: **один главный агент** `factory-lead` на DeepSeek V4.1 Flash 1017 с максимальным reasoning и **четыре субагента**. Главный агент — архитектор и диспетчер: он проектирует контракты, разбивает работу на атомарные подзадачи, запускает исполнителей, проверяет handoff и обновляет состояние. Production-код он не пишет.

## Что уже есть

- 1 primary-профиль: `.opencode/agents/factory-lead.md`.
- 4 subagent-профиля: `frontend-ui`, `logic-state`, `backend-db`, `qa-universal`.
- Единый протокол максимального рассуждения: `factory/REASONING-PROTOCOL.md`.
- Конвейер, зависимости и quality gates: `factory/PIPELINE.md`.
- Контракт передачи между агентами: `factory/HANDOFF-SCHEMA.md`.
- Состояние конвейера: `factory/state/pipeline-state.json`.
- Журнал запусков: `factory/runs/`.
- Артефакты: `factory/artifacts/00-intake/` … `04-qa/`.
- Места для тестов: `tests/unit/`, `tests/e2e/`.
- Проектный конфиг OpenCode: `opencode.jsonc`.

## Честно о «максимальном рассуждении»

- `factory-lead` использует `deepseek-v4.1-flash#max` — максимальный доступный вариант DeepSeek V4.1 Flash 1017.
- У `hy4-flash-free` доступны `none` и `high`; `high` — максимум для этой модели.
- У `beam-free` доступны `low`, `medium`, `high`, `xhigh`, `max`; выбран `max`.
- У `hungerg-free` вариантов нет. Для двух агентов на HungerG максимальный режим держится системным промтом и обязательным `<thinking>`-журналом.
- `<thinking>` — это **видимый рабочий журнал**, а не доступ к скрытым токенам модели. Провайдер может дополнительно скрывать внутренние рассуждения; контракт фабрики требует именно видимый журнал перед кодом и выводами.
- Жёсткий контракт: первый символ ответа — `<`; ответ без `<thinking>` в начале не принимается.
- Если субагент пропустил `<thinking>`, `factory-lead` возвращает задачу с требованием переписать ответ. Проверено на практике.

## Как запускать

`opencode.jsonc` уже содержит:

```jsonc
"default_agent": "factory-lead",
"model": "opencode-go/deepseek-v4.1-flash"
```

Это значит:

- новые сессии OpenCode начинаются с `factory-lead`;
- базовая модель проекта — DeepSeek V4.1 Flash 1017;
- вариант `#max` задан в профиле `factory-lead`;
- текущую сессию нужно переключить на `factory-lead` вручную, если она была создана раньше;
- если сессия уже существует, выбери агента `factory-lead` и модель `opencode-go/deepseek-v4.1-flash#max` через `/models` — сессия хранит выбранную модель отдельно от конфига;
- остальные четыре профиля нельзя выбрать как primary — они доступны только как субагенты главного.

Дай задачу главному агенту:

```text
Спроектируй архитектуру сайта с кейсами, разбей работу на атомарные подзадачи
и распредели их между frontend-ui, logic-state, backend-db и qa-universal.
Сначала обнови architecture.md, contracts.md, decomposition.md и file-ownership.md.
```

Главный агент сам:

1. прочитает состояние и handoff;
2. спроектирует архитектуру, UI/API-контракты и декомпозицию;
3. запустит нужных субагентов;
4. проверит `<thinking>`, handoff и файлы;
5. обновит `factory/state/pipeline-state.json`;
6. отчитается и остановится перед решением, которое требует человека.

### Порядок первого запуска

1. `factory-lead` — архитектура, контракты, декомпозиция, file ownership.
2. Параллельно:
   - `frontend-ui` — UI по контракту;
   - `backend-db` — API и схемы по контракту.
3. `logic-state` — связывает UI, состояние и API.
4. `qa-universal` — тесты, ревью, мелкие исправления, README/docs.
5. `factory-lead` — приёмка gates и итоговый отчёт.

Подробные зависимости и gates — в `factory/PIPELINE.md`.

## Границы

- Проект остаётся локальным демо: без реальных платежей, вывода и мультиплеера.
- Авторизация — только демо-слой без сбора персональных данных; реальные аккаунты требуют отдельного согласования.
- Баланс, инвентарь, пополнение, лайв-фид и батлы — демонстрационные.
- Секреты живут только в `.env`; агенты не читают и не пишут `.env*`, `secrets/**`.
- Коммит, push, деплой и внешние расходы — отдельные действия с разрешения пользователя.
- Продуктовые источники правды: `AGENTS.md`, `brief.md`, `PRODUCT.md`, `templates/`, код.

## Проверка готовности базы

Запусти:

```bash
node scripts/validate-factory.mjs
```

Валидатор проверяет:

- 1 primary-профиль `factory-lead` с моделью `deepseek-v4.1-flash#max`;
- 4 subagent-профиля на месте и валидны как Markdown с frontmatter;
- ровно 5 профилей в `.opencode/agents` — без старых восьми;
- у каждого агента есть `MAXIMUM REASONING` и жёсткий `<thinking>`-контракт;
- модели и варианты соответствуют доступным в провайдере;
- `factory-lead` может запускать только разрешённых субагентов;
- `opencode.jsonc` назначает `factory-lead` главным и запрещает чтение секретов;
- артефакты и состояние конвейера созданы.

Smoke-тест 2026-11-28: все 4 субагента загрузились, ответили `PROFILE OK` и начали ответ с `<thinking>`.

## Переносимый пресет

Чтобы использовать эту команду в другом проекте или синхронизировать её между ПК и ноутбуком, используй папку `preset/`:

```powershell
.\preset\install.cmd -Target "E:\ai\other-project"
```

```bash
./preset/install.sh --target /path/to/other-project
```

Пресет копирует 5 профилей, шаблон `factory/`, валидатор и `opencode.jsonc` в целевой проект. Существующие `factory/state`, артефакты и конфиг не перезаписываются. Подробности — в `preset/README.md`.
